Flujo: Cliente (Swagger, Postman, Frontend) → Controller → Service → PrismaService → PostgreSQL
Respuesta: El flujo es inverso, la respuesta sube por los mismos componentes.
Swagger: Disponible en /api/docs para probar la API.
Filtros de error: Capturan y formatean errores en cualquier punto del flujo.
Tests: Unitarios y E2E validan cada capa.

Descripción de Componentes

  • Controller: Recibe la petición HTTP y delega al Service.
  • Service: Lógica de negocio, validaciones y llamadas a la base de datos.
  • PrismaService: ORM que traduce las operaciones a SQL y consulta PostgreSQL.
  • PostgreSQL: Base de datos relacional donde se almacenan los datos.
  • Swagger: Interfaz visual para probar la API.
  • Filtros de error: Manejan y formatean errores globalmente.

¿Cómo probar?

  1. Abre /api/docs en tu navegador.
  2. Prueba los endpoints disponibles.
  3. Observa el flujo en los logs de la aplicación.
